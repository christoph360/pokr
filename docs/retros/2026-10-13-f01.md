# Retro: F01 rooms and voting (2026-10-13)

## Outcome

F01 meets its acceptance criteria. QA signed off after three consecutive green local runs under CI
conditions, and CI on `11ef34f` is green on chromium, firefox, webkit and mobile-chrome.

- Shipped: AC1–AC37. There are 111 api, 87 shared and 87 web unit tests, and about 360 e2e tests
  across four browser projects, all named after acceptance-criteria IDs.
- Not verified yet, and not blocking:
  - Staging-only checks: AC31 EU jurisdiction, the join-timeout close timing, and SQLite contention
    under load (`infra/README.md`, `docs/qa/F01-report.md`).
  - Manual checks: VoiceOver, real iOS, Edge, 400% zoom, forced colours, and p95 latency.
  - AC36 has no rename-UI e2e test; only the protocol is covered.
- Not deployed: the Cloudflare secrets and GitHub environments aren't set up yet.

Commits: `943cc2d` (contract), `48fd47e` and `e857ffc` (rate limits, deploy gating), `02ce748`
(implementation), then `2011d4d`, `4cdf000`, `368cc88`, `8b911ca` and `11ef34f` (QA findings, the e2e
suite, the CI matrix).

**User's view.**
- Went well: QA caught spec issues early, problems were fixed at the root rather than patched,
  agents worked in parallel, and decisions were brought to the user.
- Frustrating: too many loops before sign-off, CI broke after pushes, and long waits on agents.

## Per agent

### frontend-dev

- Went well: 87 unit tests, no contract mismatches, and quick turnaround on QA findings.
- Went wrong:
  - Cards had no accessible name, because the card face was `aria-hidden`.
  - The custom deck accepted empty segments.
  - Topic and rename Save did nothing: `(ngSubmit)` was used without a form directive.

  Unit tests passed in all three cases; the problems only showed up in a real browser flow.
- Root cause: missing instruction. The unit tests called handlers directly and didn't query by
  accessible role or name, so these problems couldn't fail a unit test.

### backend-dev

- Went well:
  - Open questions were raised before guessing.
  - D1 was disproved with evidence rather than "fixed".
  - It found a latent hot alarm loop (the grace-map leak).
  - D3 was reproduced with a stress script and root-caused before any retry was added.
- Went wrong:
  - The first D3 fix added a retry backoff that opened the DO input gate, which let later commands
    overtake earlier ones. The orchestrator caught this in review.
  - Several local-workerd quirks (jurisdiction, `SQLITE_BUSY`, delayed close for silent sockets)
    were only found by QA's long runs.
  - The agent definition still points to the deprecated `@cloudflare/vitest-pool-workers`.
- Root cause: missing instruction about DO concurrency and stress testing, plus a wrong instruction
  (the test tooling name).

### devops-engineer

- Went well: the deploy gating redesign, the per-project CI matrix, and clear manual-step docs.
- Went wrong:
  - `wrangler.jsonc` was pushed unformatted, which broke CI.
  - The first deploy workflow ran on every push and failed without secrets.
  - `infra/README.md` documented `POKR_TEST_MODE:true` when the code expects `1`. The orchestrator
    fixed this.
- Root cause: missing instruction. The definition of done didn't include root `format:check` and
  `lint`, workflows weren't required to handle missing secrets, and documented commands weren't
  checked against the code.

### qa-engineer

- Went well:
  - The test plan found 29 spec issues (11 blocking) before implementation.
  - Every acceptance criterion is traced to tests.
  - No test was weakened or retried until green.
  - It found D2 and D3, and traced the WebKit hang to Playwright itself.
- Went wrong:
  - D1 was filed as a product defect, but was a harness bug: `pingIntervalMs` was defined and never
    used.
  - Local sign-off runs didn't match CI (4 workers versus 2), so the WebKit context limit only
    showed up in CI.
  - About 8 test bugs were fixed during verification: `<dialog>` count, an absent `topic-display`,
    flip animation reads, an unawaited ack, a limiter window straddle, and others.
  - Firefox can't launch locally.
- Root cause: missing instruction. There was no harness check before filing a defect and no
  CI-conditions run before sign-off.

### orchestrator (main session)

- Went well: every product decision went to the user, and the ownership boundaries held.
- Went wrong:
  - A follow-up sent while backend-dev was finishing was never delivered, so the AC31/AC32 test
    fixes had to be resent.
  - I told devops a "staging checks list" existed in `infra/README.md`; it didn't.
  - Commits early in F01 went to `main` without a full root check, which led to the format
    failure.
  - QA's suite stayed uncommitted, so CI didn't cover it until the end.
  - Agents' dev servers collided on ports, a stale `wrangler dev` held :8787, and edits during an
    `ng serve` run killed one QA run.
  - There was no `gh`, so CI error output was invisible.
- Root cause: workflow. There was no branch/PR flow, no rule to freeze code during verification,
  and no check that follow-ups were delivered.

## Changes applied

The user approved all four groups.

- `CLAUDE.md`:
  - Step 4 now requires root `format:check`, `lint`, typecheck and tests, plus stopping any dev
    servers the agent started.
  - Step 5 freezes `apps/` and `packages/` during QA runs.
  - A new "Branches and CI" section: feature branches, CI on the branch, QA's suite pushed early,
    and full checks before every commit.

  These address CI breaking after pushes and QA's suite staying out of CI.
- `.github/workflows/ci.yml` (devops): CI also runs on pushes to `feature/**`.
- `qa-engineer.md`:
  - Rule out the harness before filing a defect (D1).
  - Re-run only the affected specs during fix loops, and do final runs under `CI=1`, with the CI
    run counting as one of three (the WebKit hang, the long waits).
  - Four learnings.
- `backend-dev.md`:
  - A Durable Object concurrency rule and a load test before handoff (D3, the ordering gap).
  - Test tooling corrected to `@cloudflare/vitest-plugin`.
  - Three learnings.
- `devops-engineer.md`:
  - Root `format:check` and `lint` in the definition of done (the CI format failure).
  - Documented commands checked against the code (`POKR_TEST_MODE`).
  - Two learnings.
- `frontend-dev.md`:
  - Component tests drive the DOM by role and accessible name (`ngSubmit`, nameless cards).
  - Two learnings.
