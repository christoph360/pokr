## Loops after first implementation

| # | Finding | Real cause | Found by | Cost |
| --- | --- | --- | --- | --- |
| 1 | Markdown lists failed axe; dialogs lost focus in WebKit | Only covered by jsdom tests | frontend smoke pass | 0 QA rounds (fixed before QA) |
| 2 | About 25 failures on the suite's first run | Tests written before the UI existed (test IDs, displayed vs stored status, dialog timing) | QA | 1 round |

| 4 | 6 CI failures on `16d000a` | Harness: 250 ms test heartbeat starved on the 2-core runner; two test races | CI | 1 round |
| 5 | PR run: webkit pages never joined; close hung | Playwright WebKit hang; F02 doubled webkit's load per browser | PR CI, after sign-off | 1 round |
| 6 | PR run: AC1 lost `update_settings` | Runner froze for several seconds; the 1 s test ping killed the connection | PR CI, after sign-off | 1 round |

Rows 4–6 all came from one cause, a harness tuned on a fast Mac rather than on a 2-core runner
that freezes. They were found one at a time because each CI run surfaced the next. Rows 5 and 6
appeared only after sign-off, because the PR (and its extra CI run) was opened last. Four CI runs
were lost because a newer push cancelled them (`cancel-in-progress`).

## Per agent

### frontend-dev

- Went well:
  - no contract mismatches;
  - 229 unit tests, including an XSS corpus of about 60 cases;
  - the real-browser smoke pass, added by the orchestrator, caught two bugs before QA.
- Went wrong:
  - D1 slipped through the smoke pass. Its drag check asserted only `order[0] !== 'Export'` and
    that two contexts agree, and a wrong move satisfies both.
  - The root cause was a CSS rule (`display: none` on the CDK placeholder) that no jsdom test can
    see.
- Root cause: missing instruction. The definition of done had no real-browser pass, and nothing
  said checks must assert exact expected results.

### backend-dev

- Went well:
  - two-phase contract, with open questions raised alongside a recommendation for each;
  - the agenda sync design kept vote and presence broadcasts small (AC16);
  - the stress script with story scenarios (7,344 commands, no ordering failures);
  - 54 new tests;
  - the orchestrator's concurrency review found nothing;
  - QA found no defects.
- Went wrong: it edited `apps/web/src/app/testing/fixtures.ts` (frontend-owned) so the type
  change compiled. It flagged this itself.
- Root cause: missing instruction about fixtures owned by others when a shared type changes.

### devops-engineer

- Not involved: F02 needed no bindings or CI changes.
- Open items for devops: CI runner freezes (webkit workers, runner size, chromium sharding) and
  the Ubuntu 26 image (see Deferred).

### qa-engineer

- Went well:
  - 28 spec issues (19 blocking) found before implementation;
  - every AC traced to a test;
  - no test retried or weakened;
  - every CI flake root-caused from traces and WebSocket frames;
  - D1 was proven to be the app before filing.
- Went wrong:
  - About 25 test bugs on the first run (row status compared to stored rather than displayed,
    asynchronous dialog close, races).
  - Three successive load-related harness fixes, two of them after a "conditional" sign-off. The
    heartbeat went 250 ms → 2 s → follows the server timeout → 4 s. The WebKit pool went 30 → 12,
    plus a probe and a bounded close. CI waits went 5 s → 10 s.
- Root cause: missing instruction. Nothing required the harness to tolerate CI runner freezes,
  and local runs on a fast Mac didn't show them.

### orchestrator (main session)

- Went well:
  - merged QA and backend questions into one decision round;
  - root checks run in a clean worktree before each commit, so CI never failed on format or lint;
  - reviewed the backend's Durable Object concurrency;
  - added a frontend real-browser smoke pass before QA;
  - resumed QA after the usage-limit interruption without losing work.
- Went wrong:
  - Pushed four times over CI runs whose results I needed. `cancel-in-progress` dropped them.
  - Opened the PR only after sign-off, so its extra CI run found flakes late.
  - A zsh word-splitting bug in a watch loop wasted one CI wait.
  - The smoke-pass brief didn't ask for exact expected orders.
- Root cause: workflow. There was no rule on pushing over running CI and no rule on when to open
  the PR.

## Changes applied

The user approved all four groups.

- `CLAUDE.md`:
  - Step 5: the orchestrator opens the PR when verification starts, and sign-off needs the push
    and PR CI runs green on the final commit (loops after sign-off).
  - Branches and CI: don't push while a needed CI run is still running; batch commits (lost
    runs, waits).
- `qa-engineer.md`:
  - A test-quality rule: the harness must survive multi-second runner freezes (pings at least
    4 s, state waits of 10 s under CI).
  - The F01 WebKit learning updated to the pool relaunch at 12 contexts, the probe and the
    bounded close.
  - A new learning: assert displayed state.
- `frontend-dev.md`:
  - Definition of done: a real-browser smoke pass (chromium and webkit, desktop and phone, real
    API, axe) whose checks assert exact expected results.
  - Two learnings: the CDK placeholder size, and no host elements between `ul`/`ol` and `li`.
- `backend-dev.md`: a learning to list other owners' fixtures broken by a shared type change in
  the handoff instead of editing them.
